# B03 — Motion launch, 30 s

> Status: **specified, not run.** Brief version 0.1, written 2026-10-02 from BENCHMARK_SUITE_SPEC §3. Synthetic assets only; the product and every number are **fictional**. Specified; model eval not run (decision default Q4). Hebrew and English forms (**B03-he**, **B03-en**) of equivalent complexity.
> Companion: `motion-graphics.rubric.md`, `critic-brief.md`, `bands.json`, `agent-content/techniques/frame-spec-prompt.md`, `clean-smooth-motion.md`.

## 1. Task

Render a **30 s launch piece (16:9 master 1920×1080, 30 fps = 900 frames; a 9:16 re-layout is optional and scored separately)** of a supplied synthetic UI, with Hebrew, Latin and numbers, following a **defined reveal sequence**. The author writes the frame-spec PROMPT.md (and gets it "approved" by the scripted owner) **before** any composition code; the benchmark measures how faithfully the render follows the frozen event timeline.

## 2. Frozen inputs (generator contract — `fixtures/generators/b03/`)

| Input | Specification |
|---|---|
| UI | `ui/` — a fictional invoicing dashboard "Tally" as static HTML/CSS/JSON (a card list of 5 customers with Hebrew names and Latin company names, amounts in ₪ and %, one chart), plus `screenshot.png` of the same screen for the screenshot-rebuild path. Content is invented. |
| data | `data.json`: the amounts and the *allowed value set* for every number that may appear on screen (so an intermediate value is detectable) |
| event timeline | **`timeline.json` — the frozen ground truth:** event id, frame, type (enter / swap / morph / camera key / hit), element selector, easing name, target px box, duration in frames, colour hex. ≥ 40 events in 30 s with no gap > 21 f before the end card; 4 seams, each a different technique; the camera as one spline per scene with ≥ 1.2 s moves |
| palette / fonts | `palette.json` (grounds + ONE accent that first appears on a declared frame) · licensed OFL fonts (Rubik, Heebo) with licence files, delivered as files for `@font-face` |
| music stems | author-synthesised bed + drop + riser + SFX (generated by script; redistributable; `SOURCES.md` rows). Downbeats and the hit frame are in `timeline.json` |
| answers | `inputs/answers.json` for the scripted owner (length 30 s, bar, captions none, CTA text, file name) |

## 3. What is measured

| Outcome (suite spec) | Deterministic check | Human check |
|---|---|---|
| timeline fidelity | for each event: the frame at which the element reaches its declared box/state (from decoded frames or a DOM probe) vs `timeline.json`; report the **offset in frames** per event; tolerance defined before scoring | spot-check seams |
| true font use | Chrome DevTools-protocol font-usage nodes: only the supplied families, no system-fallback nodes (the E03 method) | Hebrew look-alike test at final size |
| exact geometry | rendered bbox of key elements vs `timeline.json` boxes (px); text inside the frame and the safe rows at every camera key | — |
| temporal smoothness | `motion_qa` (0 flagged ranges with coverage), event-gap check ≤ 21 f, no hold ≥ 1 s without internal movement, whole-number swaps never show a value outside `data.json` (frame-wise sampling of the number region) | playback |
| render repeatability | **decoded-frame and PCM hashes identical across ≥ 3 repeat renders of the same authored composition on the same pin** — this measures *render determinism*, not author variability | — |
| hierarchy | — | reviewers rank what they notice first per scene; compare with `timeline.json` "primary focus" |
| sound | hit within ±1 f of the picture hit; take-away 4–12 f; −14 ± 0.5 LUFS, TP ≤ −1 on the final | listening + beat test |

**Hard gates (from the rubric):** M1 (PROMPT.md approved with the three tables and four stills **before** code — verified from the gate record), M3 (motion language), M7 (sound locked), delivery gate. No intermediate wrong number at any frame = severe failure.

## 4. Constraints and run record

No paid action. HyperFrames version **pinned** and recorded (traps are version-specific); fonts from files; no `dir="rtl"` on the root; canvas rules recorded. Run record as B01 §5, plus the render settings (workers, GPU use, capture mode) and the repeat-render hashes. For a **comparison of authoring arms** only: freeze the toolkit version per batch; a bug fix mid-run closes the batch; keep old failures; count every critic and sub-agent token.

## 5. Reference numbers (informational, not targets)

A synthetic 12 s fixture rendered in 42.3–44.3 s (HyperFrames 0.8.98, single worker, software capture) on the reference machine (E01); a 40 s heavy fixture took 132.6 s with 1 worker and 88.1 s with 8 (E11). They are not comparable to a 30 s premium composition; **do not extrapolate**.

## 6. Limits

A script-generated timeline tests *fidelity to a spec*, not taste; the human hierarchy check is the only creative signal. Cross-engine SSIM would not be creative equivalence; this brief compares within one engine pin only.
