> Status: **specified, not run.** Brief version 0.1, written 2026-10-02 from BENCHMARK_SUITE_SPEC §3. **Synthetic stand-in pool only; no new generation spend.** Specified; model eval not run (decision default Q4). ## 1. Task

**Assemble a coherent 30 s story (9:16, 1080×1920 delivered; native fps of the pool = 24) from a supplied pool of pre-made clips**, using the **same pool, the same reference identities, the same script and the same audio for both arms**. This brief compares *editing* of frozen generations. A paid-generation evaluation is a **different experiment with its own budget and id**.

## 2. Frozen inputs (generator contract — `fixtures/generators/b04/`)

| Input | Specification |
|---|---|
| clip pool | 24 clips, 1.5–6 s each, 24 fps, 1080×1920, **procedurally generated** (animated shapes/silhouettes with a consistent identity per character; a lighting change per location). **Defects are injected on purpose**: morph glitch, flicker, a limb that doubles, scrambled-glyph "text", identity colour drift, a stepped-cadence clip (frames repeated), a clean long take that *is* the idea. |
| hidden labels | `pool_labels.json`: per clip and interval, the defect type and severity, plus each clip's clean window — **hidden from authors** (held by the evaluator) |
| reference identities | `identities/` — 2 character cards + 1 location card (flat PNGs) used as the continuity reference |
| script | `story.<lang>.md`: 30 s, 6–8 beats, each beat a standalone shot (design around model weaknesses); a closing line + end card text |
| audio | author-synthesised music bed + 2–3 SFX stems; a TTS voice-over (licence recorded) — **identical in both arms**; model-generated audio is not present |
| answers | `inputs/answers.json` for the scripted owner (length 30 s, look, captions, disclosure plan) |

## 3. What is measured

| Outcome (suite spec) | Deterministic check | Human check |
|---|---|---|
| shot selection | for each used clip: the used interval's overlap with its **clean window**; median shot length (target band 1.2–2.5 s, house preset); no reversed take | story/shot choice review |
| visible artifact exposure | **seconds of labelled-defect frames visible in the final cut** (from `pool_labels.json`, computed by the evaluator), per defect type and severity; covered defects (blur/whip/flash) counted separately with their cover duration | reviewers mark artifacts they notice at 1× speed |
| identity / continuity | identity-card colour/shape consistency per shot (script-measured against the cards); one grade + grain applied to all layers (measured grade/grain parameters per layer) | reviewers rate continuity |
| story comprehension | — | unaided "what happened?" answers before feedback; randomised order; arm names hidden |
| sound continuity | SFX at every transformation/cover; no dead digital silence ≥ 0.4 s mid-film below −45 LUFS; 3 s-LUFS steps ≤ +3 LU at cuts; −14 ± 0.5 LUFS, TP ≤ −1; delivery fps = native 24 | listening |
| spend | **must be `0` / not applicable — any generation call is a protocol violation** | — |

**Hard gates (from the rubric):** G1 (no visible artifact at 1×), G3 (clean windows), G6 (one look), disclosure plan row present, no generation spend, delivery gate.

## 5. Limits (read before quoting any result)

A procedural pool does **not** reproduce real model artifacts (melting anatomy, hands, text, face drift) — it tests the *selection, trimming and covering logic* against labelled defects. Results say nothing about how an editor handles a specific model's failure modes. A study with a real, rights-cleared generated pool is a separate experiment (`B04-real`), needs a licensed source of clips with documented terms, and keeps its own cost accounting.
